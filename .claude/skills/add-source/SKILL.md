# Подключение нового источника

Цель — чтобы новый источник прошёл весь путь `источник -> stg -> raw_vault` и
появился в Airflow без написания Python. Иди по шагам и после каждого проверяй.

## 1. Разобраться с источником

- Что является бизнес-ключом? Это не суррогатный id системы, а то, по чему
  сущность узнают люди: номер заказа, артикул, код магазина.
- Как понять «что нового»: есть ли надёжная колонка `updated_at`? Если нет —
  полный снимок (без `incremental`), если таблица небольшая.
- Пишет ли источник время без зоны? Тогда нужен `timezone` в конфиге.
- Есть ли персональные данные? Если да — отдельный сателлит с `pii: true`.

Посмотри похожие пайплайны: `pipelines/erp_orders.yml` (инкремент из Oracle),
`pipelines/catalog_products.yml` (файлы), `pipelines/fx_rates.yml` (API).

## 2. Запрос и конфиг

1. `sql/extract/<имя>.sql` — выборка с окном `:wm_from`/`:wm_to` (Oracle) или
   `%(wm_from)s`/`%(wm_to)s` (PostgreSQL). Бизнес-ключи связанных сущностей
   подтягивай JOIN-ом здесь же.
2. `pipelines/<имя>.yml` — имя файла совпадает с `name`. Обязательно `checks`:
   хотя бы `not_null` по ключам и `unique` по бизнес-ключу.
3. Таблица в stg — новой миграцией `sql/dwh/NNN_<имя>.sql` с колонками `_batch_id`
   и `_loaded_at`, плюс индекс по `_batch_id`.

Для нового формата файлов нужен парсер в `src/retail_dwh/ingest/parsers.py` и
тест с фикстурой в `tests/test_parsers.py`. Настоящий пример ответа положи в
`tests/fixtures/`.

## 3. Data Vault

В `models/vault.yml`:
- новый хаб, если сущность новая (`hubs`);
- линк, если источник связывает сущности (`links`);
- сателлит с атрибутами (`satellites`), разделяй по скорости изменения и по PII;
- блок в `sources` с отображением колонок stg на ключи и атрибуты.

Проверка: `retail-dwh vault-sql --table stg.<имя>` — посмотри SQL глазами,
затем `pytest tests/test_vault_model.py` — модель валидируется целиком.

## 4. Прогон на стенде

```bash
retail-dwh migrate
retail-dwh ingest <имя>
retail-dwh vault
```

Через MCP (`pipeline_status`, `batch_details`) убедись, что партия `loaded`, и
посмотри число строк в хабе и сателлите через `run_sql`.

## 5. Каталог и итог

- Если данные дойдут до витрин — описание в `catalog/datasets.yml`.
- `pytest -m "not integration"` и `ruff check` зелёные.
- DAG появится в Airflow сам: `ingest__<имя>`. Сборка DWH подпишется на
  его Asset автоматически.
